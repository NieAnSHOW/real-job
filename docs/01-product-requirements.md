# Real Job：产品需求分析（评审稿 v0.2）

日期：2026-10-26。用户确认：小范围邀请测试，后续公开发布；插件免费；所有 API 由用户自行向官方申请；Key 仅本机保存，插件不设云端密钥托管或中转服务。

本文将原始想法整理为产品需求；技术约束见 [技术可行性与架构](02-technical-feasibility.md)，官方资料核验见 [API 调研](research/api-research.md) 和 [扩展与平台协议调研](research/extension-research.md)。文中的门槛、时间和指标是建议初值，尚未经过真实业务测试。本文不代表功能已经开发或模型准确率已经验证。

## 1. 产品定义与需要解决的问题

Real Job 是面向求职者的 Chrome 侧边栏助手。用户查看招聘公司时，可以在侧边栏发起企业背景检索，查看有来源的事实、风险线索、未知事项和求职建议，减少反复跨站搜索的时间。

原始需求包含两项能力：

1. MVP：读取 BOSS 直聘上的公司信息，使用 DeepSeek Search 补充企业资料，再交给蚂蚁 `lingdt-decision-1.0-27b` 辅助判断，以“优秀／尚可／避雷”显示结果。
2. 后续：用户上传简历，结合当前职位要求与企业背景，给出匹配度百分比及依据。

这里的“真实有效性”需要拆为三个问题，否则一个评级会混淆不同含义：

| 问题 | 可以检查的内容 | 不能仅靠公开搜索确认的内容 |
|---|---|---|
| 企业身份是否真实 | 法人主体、登记状态、品牌与主体关系、公开地址及业务 | 招聘账号一定由该主体授权、企业实际现金流 |
| 当前招聘是否可信 | 发布主体与用工主体一致性、职位描述矛盾、公开可核实的收费或欺诈线索 | 职位一定在招、招聘一定有预算、承诺一定兑现 |
| 是否值得进一步接触 | 经营及劳动用工风险、公开评价、已知条件与用户偏好的关系 | 实际团队氛围、直属领导风格、保证不裁员或不欠薪 |

产品承诺限定为“基于可获取公开信息的求职风险辅助判断”。“优秀”也必须附带评价范围和资料时间，不能包装为企业认证、信用评级或入职保证。

## 2. 首期用户与成功标准

目标用户是正在通过 BOSS 直聘筛选公司的个人求职者。首期建议邀请 20—50 人，覆盖应届生、转职者和有明确风险偏好的用户；人数是试点建议，不是已确认规模。

典型任务：

- 我只知道一个招聘品牌，希望确认实际是哪家法人公司。
- 我不想为了一个职位分别搜索官网、企业资料和评价，希望看到能追溯的汇总。
- 我看到“参保人数很少”或“网上有人说欠薪”，希望知道证据是否足够、属于哪一年、是否就是这家公司。
- 我需要知道面试时该追问什么，而不只是得到一个颜色标签。

首期成功标准按优先级排序：主体不串、事实可追溯、信息不足时能停止评级、用户能据此决定下一步。评价准确性和节省时间需要用样本评估，不能用报告生成成功率替代。

## 3. MVP 范围与发布约束

### 3.1 自动采集存在实际的平台约束

2026-10-26 访问的 BOSS 官方用户协议第七节明确列出未经许可通过插件获取平台数据的限制。完整原文和页面版本信息见 [协议核验](research/extension-research.md)。因此“用户点击后读取可见 DOM”虽然技术上可实现，却不能据此认定已经取得平台许可。

需求保留 BOSS 自动读取能力，但把它标为**受平台许可约束的模块**。取得适当许可并完成条款适用评估前，邀请测试使用用户手动输入公司全称、城市或用户有权提供的资料，验证检索、证据和决策能力；不把小范围测试视为自动采集限制的豁免。

手动入口必须明确：用户输入的名称是待核验线索，不证明它就是当前招聘页面对应的主体。它也不意味着允许批量复制平台内容或绕过平台限制。

### 3.3 免费插件与官方 API 自备密钥

这是用户确定的产品约束，适用于 MVP 及后续模块：

- 插件本身免费，不提供订阅、充值、积分、付费解锁、API 转售或代付服务。
- DeepSeek、蚂蚁以及未来抽取/企业数据服务都只使用服务商官方 API；用户在官方平台独立注册、申请、充值或购买，费用直接由官方收取。
- 设置页为每项服务提供“前往官方申请”“打开官方文档”和“管理/撤销 Key”的入口。地址见 [官方 API 申请与配置指南](research/official-api-setup.md)；未核实的深层页面不猜造，使用已核实官方平台入口。
- Key 由用户在扩展自身设置页输入，保存在本机的扩展存储中，不上传插件开发者、自有服务器、第三方代理、云配置、遥测或同步服务。
- 调用官方 API 时必须通过 HTTPS 将 Key 作为鉴权凭据发送给对应官方服务；因此准确承诺是“Key 本地保存、仅用于官方直连鉴权”，不能宣传“Key 从不离开设备”。若要求连官方鉴权也不发送，所选远程 API 就无法调用。
- 企业检索词、证据包，以及 P1 经用户确认的脱敏简历片段，按功能需要直达对应官方 API。插件无自有云端不等于这些分析完全离线。
- 不内置开发者的共享 Key，不支持聚合 API、中转商或任意自定义网关；新增服务须先核验官方身份、接口与申请地址。

### 3.4 API 设置页与配置状态

每张服务卡显示服务用途、官方申请链接、官方文档、Key 输入框、本机保存方式、已核验的官方端点及连接状态。Key 默认遮罩；已保存时只显示配置状态或短尾号，不重新输出完整值。不把 Key 放入跳转 URL、二维码、剪贴板或诊断导出。

用户可选择“仅本次会话”或“保存到本机”，并可替换/删除。点击“验证连接”才发起官方请求，若验证需实际推理或搜索，应事先说明可能产生官方费用；不假设所有服务有免费验证接口。设置页不自动替用户注册、购买或充值。

配置状态至少包含未配置、仅本次会话、已本机保存、验证成功、认证失败、服务未开通、余额不足、限流及网络不可达。必须按实际返回区分；无法确认原因时不强称余额或 Key 错误。没有某服务的 Key 时关闭对应调用并展示申请入口，不偷偷切换供应商。

## 4. 用户流程

### 4.1 首次使用

邀请仅用于招募测试者和分发插件，不建立插件账号。用户打开侧边栏，看到“插件免费，官方 API 费用由用户自行承担”的说明，以及数据流向与本机保存策略。随后前往官方平台开通服务，在插件设置中填写自己的 Key，选择仅本次会话使用或保存到本机。主动验证连接后输入公司名称；没有配置时仍可查看引导和本地历史，不替用户发起付费调用。未来启用页面读取时，再申请对应权限，不在安装时申请所有网站访问权。

### 4.2 一次企业分析

1. **取得线索**：手动输入；平台许可满足后，支持“读取当前页面”。
2. **确认主体**：显示公司全称、城市及可用的标识信息。有同名候选则选定；品牌、母公司、子公司不能默认合并。用户选择也需要后续证据核实。
3. **展示发送摘要**：首次调用时说明必要企业字段直达哪些官方服务，Key 仅用于对应官方接口鉴权；后续按已告知的使用方式执行，不经过插件运营方服务器。
4. **检索资料**：先核查主体，再查业务/用工/风险与正向信息，避免只搜负面词。
5. **整理证据**：去重、标注时间、区分事实与意见，保留矛盾和缺失。
6. **分析并校验**：证据未达门槛则直接暂不评级；有足够资料时调用决策模型，随后做规则和引用校验。
7. **展示结果**：先显示主体和结论范围，再显示原因、证据与待核实问题。
8. **后续操作**：打开来源、反馈错误、手动刷新、删除历史。刷新显示检索时间，不将缓存结果伪装成刚刚检索。

遇到主体无法确认时，停止该主体的风险评级，不继续把多家公司的信息合并喂给模型。

### 4.3 侧边栏内容顺序

| 区域 | 内容与交互 |
|---|---|
| 当前分析对象 | 公司全称、城市、品牌/主体关系、信息截至日期；可修改主体 |
| 结论卡 | 优秀／尚可／避雷，或“资料不足，暂不评级”；明确是公开信息评价 |
| 主要依据 | 最多三条优先原因，每条可展开证据；无依据不补写理由 |
| 企业事实 | 登记状态、规模描述、公开参保数据及年份、公开业务信息 |
| 风险与矛盾 | 已核实风险、待核实线索分开；标明严重程度与时间 |
| 信息缺口 | 未取得的资料、只取得摘要的事项、冲突未解决的事项 |
| 求职建议 | 下一步行动和具体面试问题，如“劳动合同由哪一主体签署” |
| 来源与操作 | 来源链接、刷新、反馈、删除；个人联系方式不在摘要中扩散 |

窄屏默认按纵向卡片显示，不强制固定宽度；颜色配合文字，不只靠红绿区分。浏览器允许用户决定侧边栏左右位置，产品不承诺强制右侧。

## 5. 公司信息与证据需求

### 5.1 页面及输入字段

| 字段 | 必需性 | 处理规则 |
|---|---|---|
| 公司显示名 | 必需 | 原样保留，不能自动认定为工商全称 |
| 法人全称、统一社会信用代码 | 有则读取/核验 | 信用代码是优先主体键；缺失时不编造 |
| 城市、公开地址、行业 | 辅助 | 用于同名消歧；办公地址与注册地址分别记录 |
| 平台规模、融资描述 | 可选 | 标为平台展示/企业自述，不能当已审计事实 |
| 来源 URL、获取时间 | 自动读取时必需 | 去除不必要查询参数；不上传带会话信息的 URL |
| 职位标题、薪资、经验、学历、职责 | P1 或明确的招聘风险分析 | 仅在该功能需要且已告知时采集；公司评价默认不上传整份岗位文本 |

### 5.2 外部资料及可用边界

| 维度 | 目标资料 | 常见局限 |
|---|---|---|
| 主体身份 | 登记名称、登记状态、品牌关系、变更信息 | 搜索可能没有覆盖；关联公司不能互相代替 |
| 人员基础 | 公开人员规模、公开年报参保人数、团队与高管公开职务信息 | 统计口径、法人边界和年份不同；不收集员工名册或私人信息 |
| 社保 | 可合法获取的企业层面参保人数、所属年度、披露主体 | 不等于当前员工数、实际参保比例或按时足额缴费证明 |
| 经营与信用 | 公开行政处罚、经营异常、注销吊销状态、诉讼等 | 出现诉讼不等于败诉；历史事项可能已解决，案由也可能与求职无关 |
| 舆论与劳动用工 | 新闻、公开劳动争议资料、员工评价、投诉线索 | 需核对同名、时间、转载源头；匿名评价只能作为线索 |
| 业务与招聘一致性 | 官网业务、岗位职责、办公地点、签约主体等 | 官网属于自述；真实主体也可能存在虚假或过期招聘 |

**缺失是单独的数据状态。** 参保人数 `null` 不等于 0；0 也不自动等于“没有员工”或“不缴社保”。母子公司分开参保、派遣/外包、统计年度滞后都需要核实，不能由模型补全。

### 5.3 证据卡片最低要求

每条证据记录：证据 ID、对应主体、主张、原文摘录、来源 URL/标题/发布者、事件时间、发布时间、检索时间、正文或摘要、来源类型、事实/自述/意见、是否有冲突、适用维度。

“搜索找到”与“正文核实”必须区分。没有正文、没有日期或只有标题时，允许保留线索，不能将其显示为已核实的严重风险。相同新闻被多站转载只算一个事件来源。

来源强度建议分为：政府/监管/有效法律文书等可核实原始材料；具有明确署名和事实依据的报道；公司自述；匿名评价/聚合摘要。分类不能由域名或搜索服务的 `authority` 字段单独决定，需检查内容、主体、时效和相关性。

## 6. 评级策略

### 6.1 用户标签与系统状态

| 展示 | 定义 | 不得表达的含义 |
|---|---|---|
| 优秀 | 主体清楚、关键资料较完整，存在支持继续了解的正向依据，未发现已核实重大风险 | 认证好公司、保证待遇和工作体验 |
| 尚可 | 主体与基本经营状态可核实，已有一定求职相关信息，当前证据支持继续接触并核实具体事项 | 所有风险都排除、信息少也可默认放心 |
| 避雷 | 同一主体存在达到严格证据门槛的重大当前求职风险，建议暂缓接触 | 根据匿名差评或模型感觉给企业定性 |
| 暂不评级 | 主体未确定、证据不足、重要冲突未解决或服务失败 | 第四个风险等级或低质量企业 |

系统存储 `assessment_status` 与 `rating` 两个字段。状态可以是 `rated / insufficient_evidence / entity_unresolved / needs_review / failed`；除 `rated` 外，`rating = null`。原有三个标签得到保留，也允许模型与系统拒绝强行三选一。

### 6.2 证据门槛与裁决顺序

以下是首期建议规则，须用标注集校准；它们不是已被验证的企业信用模型。

1. **主体门槛**：实体关系可核实；同名或关联主体不清楚时停止评级。
2. **重大风险通道**：有可核实原始来源，明确对应本主体，事件类型与求职直接相关，且状态仍有效或风险仍未解决，才允许提出“避雷”。例如有效官方材料明确揭示该主体的招聘收费欺诈；注销状态与当前以该主体直接招聘的情况还需排除主体变更和代理招聘。单个执行记录、参保人数为 0、低注册资本都不自动触发。
3. **冲突门槛**：决定性证据存在未解决冲突时，显示具体风险和 `needs_review`，不输出定论。不能为了满足覆盖率把冲突忽略。
4. **普通评级门槛**：至少核实主体与登记状态，且至少有一个求职相关维度的实质资料；取得不到应有的关键资料时暂不评级。搜索无负面结果本身不算实质正向资料。
5. **优秀的附加门槛**：至少覆盖主体经营、业务/招聘一致性、劳动用工信息三个维度；至少两个独立来源链，其中有可核实权威原始资料；至少一项可核实且与当前求职相关的正向依据；无重大风险或决定性冲突。来源时间还需符合各维度有效期。企业自述福利不能单独构成正向用工证明。
6. **模型建议与本地规则约束**：模型在允许的范围内给出建议；校验不通过或模型与确定规则冲突，降为 `needs_review`，不得自动取平均或强行给“尚可”。满足重大风险通道不要求先凑齐普通评级的所有正向资料。

登记状态建议优先尝试取得近 30 天可核验材料；舆论以近 24 个月为首轮检索窗口，并对更早但仍持续的重大事项另行核实；参保数据取最新可得披露年度并明确年份。这是检索和时效策略初值，抓取时间较新不能使旧事实自动变新。超过时效要求则提示缺口或复查。

### 6.3 理由、置信度与举例

评级理由只引用证据库中的 ID，显示时由插件本地事实模板生成。模型输出的 confidence 不能标成“企业优秀概率”或“判断准确率”。首期不对用户显示概率型信心值，可显示可解释的资料完整度，例如“主体已核实；用工资料不足；2 条线索待核实”。

示例均为虚构的产品行为测试，不是对真实企业的评价：

- 同名两家公司均有搜索结果：让用户确认候选并继续核验，显示“主体待确认”。
- 公司已核实，但年报参保数据缺失：显示缺失原因，不写 0；若其他关键资料也不足，暂不评级。
- 一条两年前匿名欠薪帖子：展示为待核实线索，不能单独输出“避雷”。
- 有官方材料但涉及同品牌另一子公司：保留关联线索，不将处罚直接归到当前主体。
- 官方材料与企业最新澄清存在实质冲突：显示冲突及来源，转 `needs_review`。
- 主体资料充分，只有“未搜到负面”：不能仅因此给“优秀”。

## 7. 异常与降级体验

| 情况 | 用户看到什么 | 系统行为 |
|---|---|---|
| 非支持页面或无读取权限 | “请手动输入公司名称”或重新授权提示 | 不静默采集其他标签页 |
| DOM 改版、字段缺失 | “未识别到公司全称，请确认” | 停止推测，回退输入 |
| 搜索无结果 | 已执行的检索范围及资料缺口 | 不制造公司不存在的结论 |
| 网页需要登录/验证 | “该来源无法核实” | 不绕过，尝试其他获准来源 |
| 429/超时/余额不足 | 可理解的失败状态，允许稍后重试 | 有限重试；保留已取得证据 |
| 决策服务不可用 | 展示证据，标为分析未完成 | 不随机给评级，不伪装其他模型为 LingDT |
| 用户切换页面/公司 | 旧报告明确标注原主体，新主体重新确认 | 迟到结果不能覆盖当前主体 |
| 关闭面板、浏览器休眠或执行上下文丢失 | 重开后查看本地进度并选择继续 | 从检查点恢复；在途请求结果不明时先提示，不自动重发；不承诺关闭后继续分析 |

## 8. 后续：简历与职位匹配

### 8.1 功能流程

用户主动选择本机 PDF/DOCX 或粘贴文本 → 本地解析并移除不必要个人信息 → 用户确认经历/技能 → 取得有权处理的职位要求 → 区分硬要求、优先项和职责 → 匹配分析 → 展示总分、各项证据、缺口与改进建议。

原始简历文件不上传。需要官方模型辅助匹配时，先展示将发送的脱敏经历和职位片段，再由用户发起调用；选择本地文件本身不触发网络传输。首轮只支持可提取文本的 PDF 和 DOCX，建议上限 10 MB。扫描件提示切换文本或后续 OCR，不把乱码当简历内容。解析失败不产生匹配分。

企业风险与岗位匹配分开显示：能力适合某岗位，不代表应加入存在风险的公司。匹配百分比表示要求覆盖程度，不代表拿到 offer 的概率。

### 8.2 建议评分初值

| 维度 | 权重 | 对齐依据 |
|---|---:|---|
| 核心技能 | 35 | 职位明确要求与简历技能/项目证据 |
| 相关经验 | 25 | 工作职责、领域、实际年限；重叠经历不重复累计 |
| 项目成果 | 15 | 与岗位任务接近的成果、复杂度和责任 |
| 明确资格 | 15 | 岗位相关的学历、证照等明确要求；不推断缺失信息 |
| 用户条件 | 10 | 用户主动填写的城市、薪资、工作方式等偏好 |

每个要求设重要度及满足程度：满足 1，部分满足 0.5，不满足 0，未知单独记录。模型辅助对齐证据，权重和算分由插件本地执行；每个 0/0.5/1 均要能定位岗位和简历片段。

对于明确不适用的维度，用户确认后移出分母并重新归一；未知不能按“不适用”删除。设适用要求总权重为 W、已知要求权重为 K、已知加权得分为 P；W=0 时不计算，提示“职位要求不足，请补充”。W>0 时信息覆盖率为 K/W，匹配范围为 `[P/W, (P + W - K)/W] × 100%`。缺失越多，范围越宽。

当覆盖率低于建议阈值 80%，或任一硬要求仍未知时，只展示范围和缺口，不展示单一百分比。其余情况下显示经整数取整的保守已证实匹配度 `P/W × 100%`，并同时显示覆盖率与可能范围；所有要求均已知时范围收敛为一个数。80% 是待验证的产品阈值。

硬要求明确不满足时，单独显示“存在硬性缺口”，不能被其他高分掩盖。性别、婚育、民族、宗教、健康等非岗位能力信息不作为匹配评分输入；原始职位包含此类要求时不能照搬进打分规则。学历仅对明确、合法且与岗位有关的要求使用，不采用隐含的学校声望分。

### 8.3 后续验收重点

解析结果可编辑；每条匹配有双侧证据；缺失字段不编造；跨简历版本不串用；招聘要求中的恶意提示不影响系统规则；删除简历同时清除关联缓存和匹配报告。简历文本与联系方式不发送给搜索接口。

## 9. 非功能需求与数据管理

| 类别 | 首期建议要求 |
|---|---|
| 可解释性 | 所有决定性事实有可核验来源；模型建议、事实、未证实线索明确区分 |
| 速度 | 本地任务创建目标 2 秒内；面板保持打开时自动执行目标 15—60 秒，累计 120 秒截止；用户本地核实证据单独等待，建议 24 小时超期后暂不评级；均需实测 |
| 可靠性 | 超时、后台回收、重复点击、切页都不导致错绑结果或重复无界计费 |
| 安全 | Key 仅在扩展可信上下文本机保存，按服务商隔离；只对已核验官方 HTTPS API 鉴权，不进入网页脚本、日志、报告、导出或浏览器同步 |
| 隐私 | 必要字段仅直达用户配置的官方 API，首次明确告知；无插件自有云端或自动遥测；不上传整页、聊天、Cookie、浏览历史 |
| 调用控制 | 本地同一配置同时 1 个分析；用户可设置请求预算和费用提示；官方账号限额与账单以官方为准，本地控制不等于硬计费上限 |
| 可维护性 | 页面适配、搜索服务、证据处理、决策模型各自独立；规则和模型版本可追踪 |
| 展示 | 日期、来源与资料不足状态始终可见；无不必要个人数据或未转义 HTML |

所有下述业务资料仅保存在当前浏览器配置的扩展本地存储，不跨用户共享，也不使用 `chrome.storage.sync`。建议公司证据复用缓存 7 天、报告历史 30 天、去正文的本地诊断记录 14 天；清理在启动/运行时执行，浏览器关闭期间无法保证到期即时擦除，重开时先清理再展示。用户可随时清除全部数据。

缓存复用期限与报告依据保留期分开：在来源允许的范围内，为报告冻结必要摘录、来源、日期、核验状态及规则版本，随报告保留和删除。P1 原始简历默认只在解析期间临时使用，结构化简历仅用户主动选择时保存在本机；删除简历应清除关联匹配结果。

Key 可仅在本次会话使用，也可由用户点击“保存到本机”后持久保存；与普通报告数据分开管理，不自动随报告 TTL 删除。提供分别删除单个服务 Key 与清除全部配置的入口；清除时停止后续调用，尽力取消在途请求，并忽略迟到结果。已经被官方 API 接受的请求可能已经计费，删除本机 Key 也不等于官方吊销，需在官方控制台撤销才使其失效。

本机存储不等于系统保险箱；同一电脑/浏览器配置的使用者、恶意本机程序以及用户自行进行的系统备份仍可能接触数据。插件自身不提供同步或云备份，不能据此保证用户操作系统的备份永不包含扩展数据。已经直接发送给官方 API 的内容受官方保留政策约束，本地删除不能撤回这些请求。

反馈默认是本地问题标记。若用户希望向维护者反馈，由用户主动检查并分享不含 Key 的问题描述或脱敏报告；不自动上传报告、证据、简历或运行日志。维护者基于公开/获准样本改进规则，不提供在线人工审核服务。

## 10. 验收与效果评估

### 10.1 产品验收

| 编号 | 测试情境 | 通过条件 |
|---|---|---|
| A01 | 手动输入准确公司全称 | 进入主体确认与检索，结果绑定同一主体 |
| A02 | 品牌名、同名公司、子公司 | 无法消歧则暂不评级，禁止混合证据 |
| A03 | 无搜索结果、社保缺失 | 不输出不存在/零参保，不强制给三档标签 |
| A04 | 匿名负面/转载重复 | 不满足重大风险证据门槛，不因数量放大风险 |
| A05 | 模型引用不存在证据/输出异常 | 本地校验拒绝或转待复核，不显示伪造引用 |
| A06 | 服务商超时、限流、断网 | 有限重试；结果不明时由用户决定是否重发并提示可能重复计费，本地任务不重复创建 |
| A07 | 切页、多标签页、迟到结果 | 当前公司与报告始终一致 |
| A08 | 关闭重开、worker 回收 | 保留本地检查点，未知在途请求不自动重发，不宣称后台已完成 |
| A09 | 传输与权限检查 | Key 仅在对应官方 API 的鉴权头中；请求体只发已告知字段，无聊天或 Cookie；页面脚本和其他域名取不到 Key |
| A10 | 本机保存、删除与预算 | Key 不进入 sync、日志和导出；删除与更换后停止新鉴权调用；本地请求预算生效，不影响官方实际计费规则 |
| A11 | 获许可后的 BOSS 读取 | 用代表性页面验证字段正确率；页面改版时可靠退回手动输入 |

### 10.2 模型与评级评估

先建立建议规模 100—200 家企业的离线评测集，按主体混淆、资料丰富、资料稀少、已知风险、历史风险已解决、关联公司、匿名舆论等分层。训练/规则调优集与最终留出集按企业集团隔离，避免同一主体及其转载材料泄漏到两边。

两名评审独立标注事实归属、风险证据是否充分、应否拒判；分歧需记录并复核。标注只评价当时资料支持的结论，不把评审的个人好恶当企业真实质量。

- **主体识别准确率**：建议目标 ≥98%，并单独报告同名与集团场景；评价总体结果同时纳入主体识别错误。
- **避雷精确率**：建议目标 ≥95%，与重大风险召回率一起报告。样本少时给出样本数和置信区间，不凭个位数命中宣布可靠。
- **证据有效率**：决定性事实的引用可追溯率目标 100%；“链接能打开”不等于“支持该主张”，人工抽查支持关系。
- **拒判合理性**：资料不足案例应拒判；不能以提高评级覆盖率为由降低证据门槛。
- **稳定性**：同一冻结证据包多次调用时，等级变化和风险遗漏应可测量；不假定同样输入会得到完全相同的结果。
- **产品收益**：用户主观节省时间、是否看懂结论边界、是否误解为平台认证；不以点击率鼓励夸张“避雷”。

目标未达到时扩大受控评测、修改规则或继续以证据助手形态试点。不能仅靠加免责声明放行不可靠的企业定性。
